------------------------------------------------------------
1. declare_class is idempotent by name
------------------------------------------------------------
declare_class('PERSON', ...) twice -> same id: True (ee32aebe-8a86-46b2-acbd-7fbc081dc061)
Description is still the first one: 'A human individual'

------------------------------------------------------------
2. declare_relation_type requires domain/range by class name
------------------------------------------------------------
declare_relation_type('WORKED_AT', ...) twice -> same id: True

------------------------------------------------------------
3. Class hierarchy via add_is_subclass_of
------------------------------------------------------------
EMPLOYEE is_subclass_of PERSON: True
Gotcha: add_is_subclass_of does not dedupe -- calling it again adds a second,
identical IS_SUBCLASS_OF edge in the underlying graph between the same two nodes.

------------------------------------------------------------
4. declare_class_property is scoped by class_id, not global
------------------------------------------------------------
Two different PROPERTY nodes both named 'NAME': True

------------------------------------------------------------
5. consolidate_schema('merge') folds the source class into the target
------------------------------------------------------------
Before merge, Acme Corp's class_name: 'ORGANIZATION'
Acme Corp's IS_INSTANCE_OF edges after merge: ['COMPANY']
get_metadata reports the merge target: class_name='COMPANY'
ORGANIZATION is gone from the schema: ['COMPANY', 'EMPLOYEE', 'PERSON']
consolidate_schema('merge') re-points every edge that referenced the source
class -- instances, subclass links, domain/range, property definitions -- at the
target, then deletes the source node. Change events are fired for each affected
node, so a search-enabled KB stops returning the merged-away class as well.
